{# Amazon Ads: campaign performance, and bulk bid edits by rule. **This is the only page in the app that changes something at Amazon.** Every other tab reads Amazon and writes our own records. A rule here can move several hundred live bids in one click — the owner's real rule matched 299 targets carrying Rs 102,945 of weekly spend — so the UI is built around making that visible rather than convenient. Five things are deliberate: 1. **Preview and Apply are two clicks, never one.** The rule bar computes a plan and sends nothing; the preview table shows every `old -> new` with a tick per row; Apply sends only what is still ticked. Merging them would mean the first click both computed and applied. 2. **The selected count is always on screen.** "Select all campaigns" at this scale means thousands of rows, so a number next to the button is what turns it from an act of faith into a decision. 3. **kw / auto / product is a COLUMN, not decoration.** It is the Amazon endpoint the row will be written to. Keywords and targeting clauses are different APIs and the report labels both ids `keywordId`, so showing the split is how a routing bug becomes visible rather than silent. 4. **Every skipped row is named with its reason.** A row missing from a 299-row run is otherwise indistinguishable from a bug. 5. **Delegated listeners, no inline handlers.** Keyword text comes from Amazon and campaign names from the owner; building an onclick out of either is an injection waiting to happen. Same rule the Orders and Portfolio tabs follow. #}
