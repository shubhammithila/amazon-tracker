{# The operations employee's only screen. Requirement 5. Five things about this page are deliberate, and each one is load-bearing: 1. It does NOT include nav.html. Every link in that partial goes to an admin-only page, and advertising a tab that answers 403 makes the app look broken. tests/test_shipment_auth_roles.py asserts no admin href appears here, so adding the partial "for consistency" fails the suite. 2. A TABLE, and only the columns ops needs. Asked for directly: "for ops team also give the same tabular view but with only options relevant to them." One row per SKU, one number to type. The columns the owner's screen carries — 7d sales, projection, FBA stock, deficit, In stock, To make — are all planning figures, and none of them changes what gets boxed today. It was cards before, on the reasoning that a phone in a warehouse cannot scroll sideways. That was right about the constraint and wrong about the fix: 117 cards is a very long page to find one product in. The table stays scroll-free instead by pinning the product name and having exactly ONE input, so nothing the packer must reach is ever off-screen. Column order is PRODUCT · SIZE · PACKED NOW, then the reference figures. Size and the input were originally separated from the name by three numbers, so entering a count meant reading a name at the left edge and typing at the right edge — which is how a count lands on the wrong row. Size is set as large as the name, because "Chana Sattu" identifies nothing on its own: every product here comes in three or four sizes. 3. CARTONS ARE ONE NUMBER FOR THE WHOLE DAY, not a column. "carton is not item wise. it is random. like 500 units packed today in 20 cartons." A carton holds whatever was being packed when it was filled, so a per-SKU box asked a question with no answer — and the guess fed the Boxes field on a GST invoice. It lives in the save bar, next to the day's unit total. 4. Saving is explicit, never per-keystroke. Warehouse wifi drops, and an autosave that fails silently mid-list loses an hour of counting with no sign it happened. The button reports what it did, and leaving with unsaved work asks first. 5. NEVER sort the rows here. Order arrives from /shipment/packing/{date}, which is repository.load_plan_items' ORDER BY, which is logic.sort_items — the same order the morning PDF prints in. The packer works down the paper and down the screen together, so if this page reordered them he would be hunting for every line. filter() preserves order, so searching is safe. #}
