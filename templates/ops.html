{# The operations employee's only screen. Requirement 5. Four things about this page are deliberate, and each one is load-bearing: 1. It does NOT include nav.html. Every link in that partial goes to an admin-only page, and advertising a tab that answers 403 makes the app look broken. tests/test_shipment_auth_roles.py asserts no admin href appears here, so adding the partial "for consistency" fails the suite. 2. Cards, not a table. This is used on a phone held in one hand in a warehouse. A row of narrow cells needs horizontal scrolling to reach the cartons box, which is where mis-entry comes from. One SKU per block, two large number inputs, no sideways movement anywhere on the page. 3. Saving is explicit, never per-keystroke. Warehouse wifi drops, and an autosave that fails silently mid-list loses an hour of counting with no sign it happened. The button reports what it did, and leaving with unsaved work asks first. 4. NEVER sort the rows here. Order arrives from /shipment/packing/{date}, which is repository.load_plan_items' ORDER BY, which is logic.sort_items — the same order the morning PDF prints in. The packer works down the paper and down the screen together, so if this page reordered them he would be hunting for every line. filter() preserves order, so searching is safe. #}
