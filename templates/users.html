{# Create logins and decide what each person may see. Administrators only. Four things about this page are deliberate: 1. **The generated password is shown ONCE.** It is returned by the create/reset request and never stored in readable form, so there is no endpoint that could show it again. The panel says so plainly, because "I'll look it up later" is the natural assumption and it is wrong. 2. **The area list is rendered from the server's own list**, not hardcoded here. Adding an area to app/permissions.py makes it appear on this screen with the same key, label and order the server uses. A duplicated list would drift, and drift in a permissions UI means ticking a box that grants nothing. 3. **Admin is a separate switch from the tick list**, matching the model. It is described as what it is — can change other people's access — because "admin" alone reads like a seniority label rather than a capability. 4. **Disable is offered before Delete.** A departed packer's username is stamped on the packing days he submitted; deleting the row makes that history unattributable. #}

{# Deliberately type="text", not type="password". The owner is choosing a credential to hand to somebody else, not entering his own — he needs to SEE what he is typing, because he is about to read it out or write it down. Masking it would mean a typo becomes a login nobody can use, and the password cannot be retrieved afterwards to check. autocomplete="off" so the browser does not offer to save it as the owner's own password, which is what a password field on a signed-in page invites. #}
